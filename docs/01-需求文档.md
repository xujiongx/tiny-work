## 1. 背景

日常工作里有三类信息一直在流失：

1. **做过什么**——修了哪个 bug、跟谁对齐了什么、为什么做了某个决定，到了周五写周报时已经想不起来；
2. **要做什么**——待办散落在便签、聊天窗口和脑子里，重要但不紧急的事长期被挤掉；
3. **沉淀了什么**——命令、SQL、踩坑结论、好用的链接，用完就丢，下次重新查。

现有工具的问题：笔记软件太重（打开成本高、结构僵化）、待办软件只管任务不管“过程”、在线服务有隐私和持续付费的顾虑、聊天工具里的记录搜不到。

因此做一个**只属于自己的桌面工作台**：打开即记、按天归档、自动汇总，所有数据留在本机。

## 2. 产品定位

> 给一个人的、本地的、键盘优先的工作日志与轻量任务工作台。

三个关键词：

- **低摩擦**：从想到到记下 ≤ 5 秒，不选分类、不弹窗、不跳页。
- **可回看**：按天/周/月回看，知道自己时间花在哪。
- **可交付**：周报、月报一键生成，直接粘贴到工作沟通工具。

### 2.1 不是什么

- 不是团队协作工具（没有成员、评论、共享）。
- 不是云端笔记（没有账号、没有同步服务）。
- 不是重型项目管理（没有甘特图、依赖关系、工时审批）。
- 不是“第二大脑”式知识库（不做双向链接、图谱）。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G-01 | 让“记录今天做了什么”成为习惯 | 连续记录 ≥ 14 天的用户（自己）不中断 |
| G-02 | 写周报从 30 分钟降到 5 分钟 | 周五生成周报后，手工修改量 < 20% |
| G-03 | 重要事项不被遗忘 | 每周回顾时，“收集箱”清空率 ≥ 90% |
| G-04 | 数据安全可控 | 任意时刻可导出完整 JSON；备份可恢复 |
| G-05 | 打开成本足够低 | 冷启动到可输入 < 1 秒；全局唤起 < 300 ms |

### 3.2 非目标（首版明确不做）

- 多用户、分享、评论、权限。
- 云同步、账号登录、订阅。
- 移动端 App、Web 版。
- 复杂项目管理（里程碑、甘特图、资源排期）。
- 默认不接入任何在线 AI。可选的 AI 生成使用用户自带的 API Key 和 OpenAI 兼容接口，必须由用户显式触发；不支持后台自动上传。
- 附件/图片管理（首版只存文本与链接）。

## 4. 用户与场景

### 4.1 用户画像

**主要用户（P0）**：一人多项目的知识工作者，日常在电脑前工作，需要写日报/周报，重视隐私，愿意用快捷键。

**次要用户（P2）**：自由职业者/学生，用同一套工具记录学习、副业、生活事项。

### 4.2 典型一天（核心循环）

| 时间 | 场景 | 产品动作 |
| --- | --- | --- |
| 09:10 | 到工位，想想今天干什么 | 打开「今日」：写 1–3 件今日要事，从收集箱挑任务 |
| 10:30 | 刚开完会 | `⌘⇧Space` 唤起快速记录，输入“对齐了 X，结论是 Y”，打上项目标签，回车 |
| 14:00 | 修完一个 bug | `⌘N` 记录一条「完成」，可顺手勾掉关联任务 |
| 17:00 | 被打断，冒出个想法 | 记一条「想法」，进收集箱，不打断当前工作 |
| 18:30 | 收工前 | 通知提醒，打开日报：3 件完成、1 个阻塞、明天计划，选心情/精力 |
| 周五 17:30 | 写周报 | 打开「回顾」，一键生成周报草稿，改两句，复制到飞书 |

### 4.3 Jobs to be Done

- 当我刚完成一件事时，我想**用一句话记下来**，这样周五不用回忆。
- 当我要开始一天时，我想**知道今天最重要的事**，不被消息流带走。
- 当我卡住时，我想**记下阻塞点**，以便明天/周会提出。
- 当周五要交周报时，我想**从本周记录自动生成结构化草稿**。
- 当我需要复用一条命令/结论时，我想**搜到并一键复制**。
- 当我回顾一个月时，我想**看到时间分布和连续性**，判断投入是否合理。

- **P0 / MVP**：没有它产品不成立，首版必须可用。

## 6. P0 详细需求

### 6.1 今日页（F-REC-01/02/05、F-TASK-01/02、F-REV-01）

**目标**：打开应用 3 秒内知道“今天做了什么、还要做什么”。

必须包含：

1. 顶部日期、星期、连续记录天数；可切换前一天/后一天/回到今天。
2. 快速输入框：占位文案“今天做了什么？”，回车提交，`Shift+Enter` 换行。
3. 输入框下方一行可选项：类型（进展/完成/阻塞/想法/会议/学习）、项目、标签、耗时。
4. 今日时间线：时间 + 类型色点 + 内容 + 标签；悬停出现编辑/删除；支持撤销删除。
5. 今日待办：勾选、添加、拖动排序；完成的项折叠到“已完成”。
6. 今日日报入口：未写时显示“花 2 分钟回顾今天”；已写时显示摘要。
7. 今日概览：记录条数、完成任务数/总数、投入时长、涉及项目。

验收：

- 输入一句话回车后，列表立即出现该条，输入框清空且保持焦点。
- 刷新/重启应用后记录仍在。
- 编辑/删除操作 300 ms 内完成，失败有明确提示。
- 同一秒连续提交 10 条，不丢数据、不乱序。

### 6.2 记录页（F-REC-03/04）

- 左侧日历（月视图，有记录的日期显示圆点/强度），右侧按日期分组的时间线。
- 顶部搜索框：输入即搜（300 ms 防抖），匹配内容、标签、项目名。
- 筛选器：类型多选、项目、标签、时间范围（今天/本周/本月/自定义）。
- 空状态：如果没有记录，显示“这一天还没有记录” + 快捷补记按钮。
- 搜索结果高亮关键词；支持 `⌘K` 从任意页面进入。

验收：

- 1 万条记录下，关键词搜索 P95 < 100 ms。
- 筛选条件可组合，刷新后保留（存 localStorage）。
- 修改一条记录的日期后，它出现在目标日期下。

### 6.3 日报（F-REC-05）

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 今日完成 | 多行文本 / 列表 | 否 | 建议 1–3 条，可一键从“完成”类型记录带入 |
| 阻塞/问题 | 多行文本 | 否 | 周报“风险”来源 |
| 明日计划 | 多行文本 | 否 | 可一键转成明日待办 |
| 自由总结 | 多行文本 | 否 | 2000 字以内 |
| 心情 | 1–5 | 否 | 表情或色块 |
| 精力 | 1–5 | 否 | 与心情分开 |
| 今日标签 | 标签 | 否 | 自动汇总当天记录标签，可删改 |

行为：

- 自动保存（停止输入 800 ms 后），显示“已保存 · 18:42”。
- “从今日记录生成”按钮：把 `done` 类型记录填入“今日完成”，`blocker` 填入“阻塞”。
- 日报完成后，今日页显示摘要；未完成不阻塞其他功能。

### 6.4 待办（F-TASK-01/02）

- 三个默认分组：**今天**、**接下来**（有日期）、**收集箱**（无日期）。
- 任务字段：标题（必填，≤ 200 字）、备注、状态、优先级（P1）、截止日、项目、预计耗时。
- 交互：单击标题编辑；点击圆圈完成；`Space` 切换选中项完成；拖动排序。
- 完成的任务进入“已完成”，可撤销；默认显示最近 7 天完成项。
- 空状态文案要具体：“收集箱是空的。想到什么先丢进来，晚上再整理。”

验收：

- 新增任务后无需刷新即出现。
- 勾选完成后 500 ms 内给出视觉反馈，可 `⌘Z` 撤销。
- 逾期任务用强调色标出，但不制造焦虑（不做红点轰炸）。

### 6.5 项目（F-PROJ-01）

- 字段：名称（≤ 40 字）、颜色（6 选 1）、描述、状态（进行中/已归档）。
- 项目列表显示：名称、本周记录数、未完成任务数、最近一条记录时间。
- 归档项目不出现在记录/任务的默认选择器里，但历史数据仍可查看。
- 删除项目需二次确认，项目下的记录/任务变为“未归类”，不级联删除。

### 6.6 回顾与周报（F-REV-01/02）

周报模板（可编辑）：

```markdown
# 本周工作回顾（10.19 – 10.25）

## 本周完成
- …（来自“完成”记录 + 已完成任务，按项目分组）

## 关键进展
- …（来自“进展”记录，按项目分组）

## 问题与风险
- …（来自“阻塞”记录 + 日报阻塞）

## 数据
- 记录 42 条 · 完成任务 17 个 · 专注 6.5 小时
- 主要投入：项目 A（48%）、项目 B（31%）

## 下周计划
- …（来自未完成任务 + 日报“明日计划”汇总）
```

行为：

- 选择周（默认本周），点“生成周报”后进入可编辑的 Markdown 预览。
- 支持复制到剪贴板、导出 `.md`、在访达中显示。
- 生成逻辑是“确定性拼接”，不是 AI 改写；用户可修改后再次生成（覆盖前提示）。
- 空数据时给出温和提示，不生成空洞模板。

### 6.7 搜索（F-REC-04）

- 入口：`⌘K` 命令面板 / 记录页搜索框。
- 范围：记录正文、日报、任务标题/备注、片段标题/内容、项目名。
- 结果按类型分组，键盘上下选择，回车跳转并高亮。
- 首版用 SQL `LIKE` + 索引；数据量超过 5 万条再评估 FTS5。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 冷启动 < 1 s；页面切换 < 100 ms；1 万条记录搜索 P95 < 100 ms；输入无卡顿 |
| 可靠性 | 写入失败必须显式提示；每日自动备份；崩溃后数据可恢复 |
| 离线 | 核心功能 100% 离线可用；可选的 AI 生成与链接预览需要网络 |
| 隐私 | 默认不发任何网络请求；AI 只在用户显式点击时调用其配置的接口；无遥测；导出由用户主动触发 |
| 可移植 | 数据可全量导出为 JSON；Markdown 导出不依赖应用 |
| 可访问性 | 全键盘可操作；焦点可见；对比度 ≥ 4.5:1；尊重“减少动态效果” |
| 跨平台 | 以 macOS 为主；代码避免平台硬编码，Windows/Linux 可后续适配 |
| 体积 | 构建产物 < 15 MB；无 npm 运行时依赖 |

## 8. 数据与隐私原则

1. **默认不联网**：应用启动不发起网络请求。
2. **不做遥测**：不统计、不上报、不埋点。
3. **可带走**：任何时刻可导出全量数据；导出格式有版本文档。
4. **可删除**：删除项目不级联删记录；删除记录有 7 天软删除窗口；提供“彻底清空”二次确认。
5. **不引入账号**：没有登录，就没有“被锁在门外”的风险。
6. **AI 只做显式辅助**：默认不发送任何数据；用户点击生成后，只发送当前功能所需范围的记录。API Key 存在系统钥匙串，不写入数据库、不进入 JSON 导出。
7. **不自动保存 AI 结果**：日报、周报和绩效都先展示草稿或允许撤销，用户确认后才回填/保存。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 记录摩擦仍然太高 | 弃用 | 全局快捷键、默认值、无必填分类、回车即存 |
| 功能膨胀成“什么都有” | 失焦 | 严格按 P0 交付；P1 之后每加一个功能必须删/简化一个 |
| SQLite 迁移出错 | 数据损坏 | 迁移前自动备份；迁移在事务中执行；版本号校验 |
| 周报生成质量差 | 仍需手写 | 模板可编辑；按项目分组；保留原始记录可追溯 |
| 快捷键冲突 | 功能不可用 | 设置中可改；注册失败时提示并降级为应用内快捷键 |
| 长期使用数据量大 | 卡顿 | 分页加载、索引、按需统计；5 万条后评估 FTS |
| 跨平台差异 | 只在自己 Mac 可用 | 全部路径走 `app.paths()`；平台能力先探测再使用 |
