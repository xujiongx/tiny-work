# 案头 · 个人工作台 — 文档索引

> 工作名：**案头（Deskwork）**。正式名称可随时替换，不影响文档结构。
>
> 一句话：一个**完全本地、键盘优先、5 秒记一笔**的个人工作台，用来看清自己每天做了什么，并自动把流水账变成周报。

---

## 一页速览

| 项目 | 结论 |
| --- | --- |
| 产品形态 | macOS 桌面应用（tinyjs：WebView 前端 + txiki.js 后端） |
| 目标用户 | 需要写日报 / 周报、同时管多个项目的知识工作者（首先是自己） |
| 核心场景 | 日间快速记录 → 晚间 2 分钟复盘 → 周五一键生成周报 |
| 差异化 | 本地优先、无账号无云、全局快捷键随手记、记录与任务/项目/专注互相关联 |
| 数据 | SQLite（`workbench.db`），自动备份 + JSON/Markdown 导出，数据永远属于用户 |
| 前端 | 原生 HTML/CSS/JS，无框架、无构建、无 npm 依赖 |
| 后端 | txiki.js，负责 SQLite、文件、通知、菜单、全局快捷键、托盘 |
| MVP 范围 | 今日页、每日记录、日报、待办、项目、周报、搜索、备份 |
| 明确不做 | 团队协作、云同步、账号体系、甘特图、移动端、AI 自动总结（首版） |

## 已确定的决策（ADR-lite）

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D-01 | 本地优先，SQLite 单文件存储 | 记录是长期资产，不能被账号/网络绑架；查询、统计、迁移都简单 |
| D-02 | 前端不引入框架、不引入构建步骤 | 与现有 tinyjs demo 一致；`file://` 下最稳；应用规模可控 |
| D-03 | 记录（entry）与任务（task）分离，可互相转换 | 流水账偏“发生过什么”，任务偏“要做什么”，混在一起会变脏 |
| D-04 | 主窗口 + 独立“快速记录”小窗 | 不打断当前工作；全局快捷键唤起，Esc 关闭 |
| D-05 | 记录按“本地日期”归档，同时保存完整时间戳 | 跨零点、补记、周报统计都依赖稳定的归档日期 |
| D-06 | 日报是“结构化字段”而非一段自由文本 | 便于自动生成周报、统计心情/精力趋势 |
| D-07 | 周报先生成 Markdown，再由用户复制/导出 | 适配飞书、企业微信、邮件、Notion 等所有去处 |
| D-08 | 删除采用软删除，保留 7 天可撤销 | 记录类应用最怕误删 |
