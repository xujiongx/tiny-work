### 1.1 职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 前端 | DOM、状态、键盘、日期归属计算、Markdown 预览、AI 预览与撤销、输入校验提示 | 直接读写文件、SQL、系统调用、读取 API Key |
| 后端 | 数据校验、SQL、事务、迁移、备份、聚合统计、周报拼接、AI 上下文与接口调用、系统能力 | 复杂排版、日期本地化格式、UI 状态 |
| SQLite | 持久化、索引、查询 | 业务规则 |

### 1.2 关键约束（来自 tinyjs / txiki.js）

- 页面没有 `tjs` 全局，不能 `import 'tjs:sqlite'`；一切数据能力通过 `api` 暴露。
- `tjs:sqlite` **完全同步**：不要 `await`；语句只有 `run/all/finalize`，没有 `get()`，取首行用 `.all()[0]`；`run()` 不返回插入 id，需要 id 时用 `INSERT ... RETURNING id` 配 `.all()`。
- `tjs.*` 文件操作全部是异步的，必须 `await`（例如建目录后再开数据库）。
- 后端没有 `Intl`：日期格式化、周起始、友好文案全部放前端。
- 页面用 `tiny.api.call()`，后端 `throw new Error('中文提示')` 会以**字符串** reject。
- 前端不要在顶层声明 `const chrome`（WebView2 上是不可配置全局，直接语法错误）。
- 所有拼进 `innerHTML` 的用户内容必须转义。
- API Key 只能通过后端 `app.secrets.get/set/delete` 读写；任何返回前端的状态只暴露 `hasKey` 和末四位提示。
- 后端发起 AI 请求时使用 txiki.js 全局 `fetch`，不经过 WebView，因此没有 CORS 问题；请求只在用户点击按钮后发生。

### 2.1 前端为什么不用 ES module

`src/frontend/` 以 `file://` 加载。经典 `<script>` 一定可用；`type="module"` 在 `file://` 下的行为依赖 WebView 的本地文件策略，存在被 CORS 拦截的风险。首版采用**按顺序加载的 classic script + `window.WB` 命名空间**：

```html
<script src="js/util.js"></script>
<script src="js/api.js"></script>
<script src="js/store.js"></script>
<script src="js/components.js"></script>
<script src="js/ai.js"></script>
<script src="js/views/today.js"></script>
<!-- … -->
<script src="app.js"></script>
```

```js
// js/util.js
(function (WB) {
  WB.util = { escapeHtml, dateKey, addDays, debounce };
})(window.WB = window.WB || {});
```

每个文件只挂一个命名空间，避免全局污染。若后续确认 WebView 支持 `file://` module，再迁移，不影响数据层。

## 3. 数据模型

### 3.1 存储约定

| 数据 | 类型 | 约定 |
| --- | --- | --- |
| 主键 | TEXT | 32 位十六进制；JS 用 `crypto.randomUUID()`，降级 `crypto.getRandomValues` |
| 时间戳 | INTEGER | Unix epoch 毫秒（UTC），展示时在前端转本地 |
| 归档日期 | TEXT | `YYYY-MM-DD`，由前端按“一天分界”规则计算 |
| 标签 | TEXT | JSON 数组字符串，如 `["文档","对齐"]`；≤ 8 个，每个 ≤ 20 字 |
| 布尔 | INTEGER | 0/1 |
| 软删除 | INTEGER | `deleted_at` 为 null 表示未删除 |
| 设置值 | TEXT | JSON 字符串 |

> 为什么同时存 `occurred_at` 和 `entry_date`：前者用于精确排序与“几点记的”，后者用于按天归档、周报统计。跨零点补记时只改 `entry_date`，时间戳保持真实。

### 3.2 ER 关系

```text
projects 1 ─── n entries
projects 1 ─── n tasks
projects 1 ─── n focus_sessions
entries  1 ─── 0..1 focus_sessions   （专注结束时生成/关联一条记录）
tasks    1 ─── 0..n entries          （完成任务时自动写记录）

daily    按日期独立（date 主键）
snippets 独立
settings 独立

performance_reviews 1 ─── n performance_dimensions
performance_dimensions 1 ─── n performance_items
```

### 3.3 完整 DDL（migration v1）

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;

CREATE TABLE IF NOT EXISTS projects (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  color       TEXT NOT NULL DEFAULT 'moss',
  description TEXT NOT NULL DEFAULT '',
  status      TEXT NOT NULL DEFAULT 'active'
              CHECK (status IN ('active', 'archived')),
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS entries (
  id           TEXT PRIMARY KEY,
  entry_date   TEXT NOT NULL,              -- YYYY-MM-DD
  occurred_at  INTEGER NOT NULL,           -- epoch ms
  content      TEXT NOT NULL,
  kind         TEXT NOT NULL DEFAULT 'log'
               CHECK (kind IN ('log','done','blocker','idea','meeting','learning')),
  project_id   TEXT REFERENCES projects(id) ON DELETE SET NULL,
  tags         TEXT NOT NULL DEFAULT '[]',
  duration_min INTEGER CHECK (duration_min IS NULL OR duration_min >= 0),
  source       TEXT NOT NULL DEFAULT 'manual'
               CHECK (source IN ('manual','task','focus','import')),
  task_id      TEXT,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  deleted_at   INTEGER
);

CREATE INDEX IF NOT EXISTS idx_entries_date
  ON entries(entry_date, occurred_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_entries_project
  ON entries(project_id, entry_date DESC) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_entries_kind
  ON entries(kind, entry_date DESC) WHERE deleted_at IS NULL;

CREATE TABLE IF NOT EXISTS tasks (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  note          TEXT NOT NULL DEFAULT '',
  status        TEXT NOT NULL DEFAULT 'inbox'
                CHECK (status IN ('inbox','todo','doing','done','dropped')),
  priority      INTEGER NOT NULL DEFAULT 1
                CHECK (priority BETWEEN 0 AND 3),   -- 0 低 / 1 中 / 2 高 / 3 紧急
  planned_date  TEXT,                              -- YYYY-MM-DD，今天/接下来
  due_date      TEXT,                              -- YYYY-MM-DD
  project_id    TEXT REFERENCES projects(id) ON DELETE SET NULL,
  estimate_min  INTEGER,
  sort_order    INTEGER NOT NULL DEFAULT 0,
  completed_at  INTEGER,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER
);

CREATE INDEX IF NOT EXISTS idx_tasks_view
  ON tasks(status, planned_date, sort_order) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_tasks_project
  ON tasks(project_id, status) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_tasks_due
  ON tasks(due_date) WHERE deleted_at IS NULL AND status NOT IN ('done','dropped');

CREATE TABLE IF NOT EXISTS daily (
  date        TEXT PRIMARY KEY,             -- YYYY-MM-DD
  summary     TEXT NOT NULL DEFAULT '',
  highlights  TEXT NOT NULL DEFAULT '[]',  -- JSON array<string>
  blockers    TEXT NOT NULL DEFAULT '[]',
  plan_next   TEXT NOT NULL DEFAULT '[]',
  mood        INTEGER CHECK (mood IS NULL OR mood BETWEEN 1 AND 5),
  energy      INTEGER CHECK (energy IS NULL OR energy BETWEEN 1 AND 5),
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS snippets (
  id          TEXT PRIMARY KEY,
  title       TEXT NOT NULL,
  content     TEXT NOT NULL DEFAULT '',
  kind        TEXT NOT NULL DEFAULT 'snippet'
              CHECK (kind IN ('snippet','command','link')),
  language    TEXT NOT NULL DEFAULT '',
  url         TEXT NOT NULL DEFAULT '',
  tags        TEXT NOT NULL DEFAULT '[]',
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER
);

CREATE TABLE IF NOT EXISTS focus_sessions (
  id           TEXT PRIMARY KEY,
  started_at   INTEGER NOT NULL,
  ended_at     INTEGER,
  planned_min  INTEGER NOT NULL DEFAULT 25,
  actual_min   INTEGER NOT NULL DEFAULT 0,
  project_id   TEXT REFERENCES projects(id) ON DELETE SET NULL,
  entry_id     TEXT REFERENCES entries(id) ON DELETE SET NULL,
  status       TEXT NOT NULL DEFAULT 'running'
               CHECK (status IN ('running','done','abandoned')),
  note         TEXT NOT NULL DEFAULT ''
);

CREATE INDEX IF NOT EXISTS idx_focus_started
  ON focus_sessions(started_at DESC);

CREATE TABLE IF NOT EXISTS settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                    -- JSON
);

CREATE TABLE IF NOT EXISTS meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

迁移版本用 `PRAGMA user_version`：

```js
const version = db.prepare('PRAGMA user_version').all()[0].user_version;
if (version < 1) {
  db.exec(schemaV1);
  db.exec('PRAGMA user_version = 1');
}
if (version < 2) {
  db.exec(schemaV2);
  db.exec('PRAGMA user_version = 2');
}
```

每次迁移前调用 `backupBeforeMigrate()`；迁移包在 `db.transaction()` 中（注意：`exec` 多条 DDL 与 `user_version` 写在同一次事务里）。

### 3.4 数据完整性规则

| 规则 | 实现 |
| --- | --- |
| 内容非空 | 后端 trim 后校验；≤ 4000 字 |
| 类型合法 | CHECK 约束 + 后端白名单 |
| 项目必须存在且未归档（新建时） | 后端查询校验；归档项目的旧数据仍可读 |
| 标签数量 | ≤ 8，去重、trim、丢弃空串 |
| `entry_date` 格式 | 正则 `/^\d{4}-\d{2}-\d{2}$/` + 日期有效性校验 |
| 任务完成 | `status='done'` 时写 `completed_at`；恢复时清空 |
| 项目删除 | 物理删除项目，记录/任务 `project_id` 置空（`ON DELETE SET NULL`） |
| 记录删除 | 软删除；`purge` 仅在设置里手动触发 |

### 3.5 示例查询

今日时间线：

```sql
SELECT e.*, p.name AS project_name, p.color AS project_color
FROM entries e
LEFT JOIN projects p ON p.id = e.project_id
WHERE e.entry_date = ? AND e.deleted_at IS NULL
ORDER BY e.occurred_at DESC
LIMIT ? OFFSET ?;
```

本周热力图：

```sql
SELECT entry_date, COUNT(*) AS n
FROM entries
WHERE entry_date BETWEEN ? AND ? AND deleted_at IS NULL
GROUP BY entry_date;
```

周报用的项目分布：

```sql
SELECT COALESCE(p.name, '未归类') AS project, COUNT(*) AS n,
       COALESCE(SUM(e.duration_min), 0) AS minutes
FROM entries e
LEFT JOIN projects p ON p.id = e.project_id
WHERE e.entry_date BETWEEN ? AND ? AND e.deleted_at IS NULL
GROUP BY COALESCE(p.name, '未归类')
ORDER BY n DESC;
```

```sql
CREATE TABLE performance_reviews (
  id                 TEXT PRIMARY KEY,
  title              TEXT NOT NULL,
  employee_name      TEXT NOT NULL DEFAULT '',
  period             TEXT NOT NULL DEFAULT '',
  grade              TEXT NOT NULL DEFAULT '',
  status             TEXT NOT NULL DEFAULT 'draft'
                     CHECK (status IN ('draft','final')),
```

- 保存时后端整体校验并替换维度/条目，使用一个事务；空行保留，草稿不强制填写完整。

- JSON 导出版本升级为 2，包含绩效表与全部设置；旧版 version 1 文件仍可导入。

### 3.7 AI 配置与密钥

| 项 | 存储 | 说明 |
| --- | --- | --- |
| `aiEnabled` | `settings` 表 | 默认 `false`；关闭时所有 AI 按钮只提示配置，不发请求 |
| `aiBaseUrl` | `settings` 表 | 默认 `https://apihub.agnes-ai.com/v1`，可换任意 OpenAI 兼容接口 |
| `aiModel` | `settings` 表 | 默认 `agnes-2.5-flash` |
| `ai.apiKey` | 系统钥匙串 `app.secrets` | 不写 SQLite、不写 JSON、不返回前端 |

- `ai.status` 只返回 `enabled / baseUrl / model / hasKey / keyHint / secretError`，其中 `keyHint` 为 `••••` + 末四位。
- 保存时非空 Key 才写入；输入框留空表示保持原 Key；`clearKey` 显式删除。
- 钥匙串读取失败不影响其他功能，只在 AI 状态区提示，并阻止生成。
- 通过环境变量或本地文件读取 Key 不是默认行为；用户必须在设置页填写一次。

## 4. 后端 API 契约

### 4.1 约定

- 全部方法挂在 `export const api = { ... }`。
- 参数：单个对象；缺省字段按默认值处理。
- 返回：可 JSON 序列化对象；列表统一 `{ items, total, hasMore }`。
- 错误：`throw new Error('中文提示')`；前端 toast 展示。
- 写操作返回受影响对象；删除返回 `{ id, deletedAt }`。
- 事件：写成功后 `app.push('entries:changed', { date, action, id })`，前端据此刷新当前视图。
- 分页：`limit` 默认 100、上限 500；`offset` 默认 0。

## 5. 关键业务逻辑

### 5.1 一天的分界

前端统一计算，后端只校验格式：

```js
function entryDateFor(ts, boundaryHour = 0) {
  const d = new Date(ts);
  if (d.getHours() < boundaryHour) d.setDate(d.getDate() - 1);
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`;
}
```

- 默认 `boundaryHour = 0`；设置里可改 4。
- 补记时允许显式传 `entryDate`，但仍校验其与 `occurredAt` 的差距 ≤ 31 天，防止误操作。

### 5.2 周报生成

确定性拼接，不调用任何模型：

```text
1. 取区间内 entries（未删除）+ tasks（completed_at 在区间内）
2. 按项目分组；未归类单独一组
3. 本周完成 ← kind='done' 的记录 + 已完成任务（去重：task_id 关联）
4. 关键进展 ← kind='log' 的记录，按项目折叠为要点
5. 问题与风险 ← kind='blocker' + daily.blockers
6. 数据 ← stats.overview + stats.breakdown
7. 下周计划 ← status IN ('inbox','todo','doing') 且 planned_date 为空/已过期
8. 套模板，返回 markdown 字符串
```

去重规则：

- 同一个任务完成生成的记录（`source='task'`, `task_id` 非空）只出现一次，优先用任务标题。
- 相同文本（trim 后完全一致）在同一天合并，保留最早时间。

模板占位符（首版固定，P2 再开放自定义）：

```text
{{range}} {{completed}} {{progress}} {{risks}} {{metrics}} {{next}}
```

### 5.3 搜索

首版：

```sql
SELECT e.*, p.name AS project_name
FROM entries e
LEFT JOIN projects p ON p.id = e.project_id
WHERE e.deleted_at IS NULL
  AND (e.content LIKE '%' || ? || '%' OR e.tags LIKE '%' || ? || '%')
ORDER BY e.occurred_at DESC
LIMIT ?;
```

- 转义 `%`、`_`，用 `ESCAPE '\'`。
- 中文不分词，`LIKE` 足够；英文大小写不敏感（SQLite 默认 ASCII）。
- 超过 5 万条或搜索 P95 > 100 ms 时，增加 FTS5 虚拟表 + 触发器同步（P2）。

### 5.4 备份

```js
async function backupNow(app) {
  const dir = (await app.paths()).data + '/backups';
  await tjs.makeDir(dir, { recursive: true });
  const name = `workbench-${stamp()}.db`;
  const path = `${dir}/${name}`;
  db.prepare('VACUUM INTO ?').run(path);   // 事务外执行
  pruneOldBackups(dir, settings.backupKeep);
  return { path, at: Date.now() };
}
```

- 触发：应用启动后首次写入前（每天最多一次）、手动“立即备份”、迁移前。
- 保留份数默认 7；按文件名时间排序删除最旧。
- 恢复：设置页“从备份恢复…”→ 选择文件 → 校验 `PRAGMA integrity_check` → 备份当前库 → 覆盖 → 重启后端。首版可只提供“在访达中显示”，恢复流程放 P1，避免误操作。

### 5.5 导入导出

JSON 格式（带版本；v2 起包含绩效表和 AI 非敏感设置）：

```json
{
  "format": "deskwork",
  "version": 2,
  "exportedAt": 1761200000000,
  "projects": [],
  "entries": [],
  "tasks": [],
  "daily": [],
  "snippets": [],
  "focusSessions": [],
  "performance": { "reviews": [], "dimensions": [], "items": [] },
  "settings": { "aiEnabled": false, "aiBaseUrl": "...", "aiModel": "..." }
}
```

- **API Key 永远不进入导出文件**；`settings` 只含 `aiEnabled / aiBaseUrl / aiModel`。
- 导入 v1 文件时，绩效表保持为空；当前数据库已有数据不受影响。

- 导出使用 `tiny.dialog.saveFile()` 选路径，后端写文件。
- 导入在事务中执行；`merge` 按 id 去重（已存在则跳过），`replace` 先清空再写入（二次确认 + 自动备份）。
- 兼容旧 demo：读取 `app.store.get('lines')`，把每条 `{id,text}` 导入为 `entry_date = 导入日`、`kind='idea'`、`source='import'`，打标签 `旧便签`。

### 5.6 AI 生成（可选）

#### 请求链路

```text
按钮点击
  → 前端 ai.ensure()：读取 ai.status
  → 未启用/无 Key：弹配置提示，不请求网络
  → 后端收集上下文（只读、确定性、有长度上限）
  → POST {aiBaseUrl}/chat/completions
      Header: Authorization: Bearer <keychain key>
      Body: { model, messages, temperature, max_tokens, stream: false }
  → 60–90 秒超时；非 2xx、空内容、格式错误都转成中文错误
  → 日报/绩效：严格 JSON 解析 → 白名单字段校验 → 返回草稿
  → 周报：Markdown 文本 → 检查五段结构 → 返回草稿
```

#### 上下文范围

| 功能 | 读取的数据 | 长度控制 |
| --- | --- | --- |
| AI 日报 | 当天记录、当天完成任务、当天相关未完成任务、已有日报、最近 3 天日报 | 约 14k 字符 |
| AI 周报 | 区间确定性草稿、统计、项目分布、区间日报 | 约 24k 字符 |
| AI 绩效 | 考核周期记录、完成任务、日报摘要、当前评价表、同员工上一份评价表 | 约 30k 字符 |

- 所有查询都带 `deleted_at IS NULL`；按 `entry_date` / `completed_at` 归属周期。
- 周期解析支持 `2026 Q3`、`2026年第三季度`、`2026-07`；解析失败直接提示，不猜范围。
- 提示词明确要求“只使用材料中的事实，不编造数字/客户/项目”，并限定每条长度和 JSON 结构。
- 解析失败不重试扣费；返回中文错误，前端保留原内容。

#### 回填与撤销

| 功能 | 交互 | 落库时机 |
| --- | --- | --- |
| 日报 | 可编辑预览 → 填入 → 自动保存；toast 撤销 | 填入后 |
| 周报 | 直接替换 textarea；toast 撤销 | 不落库（复制/导出由用户决定） |
| 绩效 | 可编辑预览 → 只填空行 / 覆盖全部 → 编辑表单 | 用户点保存后 |

- 绩效 AI 草稿只在内存里，不调用 `performance.save`；关闭编辑器即丢弃。
- 撤销快照在内存中保留，不写数据库；应用重启后不可撤销。
- 嵌套模态框的 Escape 只关闭最上层，避免误关编辑器。

#### 安全与隐私

- 页面永远拿不到 Key，也拿不到完整请求体。
- 不发遥测；不记录 prompt/response 到日志文件。
- 接口地址由用户填写，默认值只是方便；切换服务商不需要改代码。
- 钥匙串在开发版与构建版可能触发一次系统授权，这是 macOS Keychain ACL 行为。

## 6. 前端设计

### 6.1 启动流程

```text
DOMContentLoaded
  → 注册全局错误处理（window.onerror / unhandledrejection → toast）
  → api.bootstrap({ date: today })
  → 填充 store（settings/projects/counts）
  → 根据 hash 或 store.view 渲染视图
  → 聚焦当前视图的主动作
  → 订阅数据变更事件
```

路由用 `location.hash`（`#/today`、`#/journal?date=…`），不引入路由库。刷新后保持当前页。

### 6.2 状态

```js
WB.store = {
  state: {
    view: 'today',
    date: '2026-10-23',
    settings: {},
    projects: [],
    entries: [],
    tasks: [],
    daily: null,
    filters: { kind: null, projectId: null, tag: null, query: '' },
    loading: false,
  },
  set(patch) { …; this.emit(); },
  subscribe(fn) { …; return unsubscribe; },
};
```

- 单一状态树，视图订阅后整体重渲染自己的容器（数据量小，简单可靠）。
- 输入中的临时值不进全局状态（避免光标跳动）。
- 列表增量更新只在“时间线插入一条”这种高频场景使用，其余整块重渲染。

### 6.3 渲染与安全

```js
function esc(s) {
  return String(s).replace(/[&<>"']/g, (c) => ({
    '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;',
  })[c]);
}
```

- 用户内容一律先 `esc()` 再进模板字符串；能用 `textContent` 就不用 `innerHTML`。
- 搜索高亮：先转义，再对转义后的安全字符串做关键词包裹 `<mark>`，且关键词同样转义。
- 禁止 `eval` / `new Function` / 远程脚本。
- `index.html` 加 CSP：

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'">
```

> `style-src` 的 `'unsafe-inline'` 仅用于必要的动态样式（如热力图色阶），若改为 CSS 变量则尽量去掉。

### 6.4 键盘

| 快捷键 | 作用 | 作用域 |
| --- | --- | --- |
| `⌘1…⌘7` | 切换页面 | 全局 |
| `⌘K` | 命令面板 / 搜索 | 全局 |

实现：单个 `keydown` 监听 + `data-shortcut` 映射；输入框内只处理 `⌘Enter`/`Esc`，不劫持普通字符。全局系统快捷键用 `tiny.hotkey.register('quick-capture', 'cmd+shift+space')`，注册失败要捕获并提示。

### 6.5 日期与格式化

- 前端用 `Intl.DateTimeFormat` 格式化（后端没有 Intl）。
- 统一函数：`fmtDate`、`fmtTime`、`fmtWeekday`、`fmtRange`、`startOfWeek(date, mondayFirst)`。
- 所有跨天计算基于本地时间；不用 UTC 字符串截断。
- 相对时间（“3 分钟前”）只用于最近 24 小时，超过则显示日期。

## 7. 性能

| 场景 | 目标 | 手段 |
| --- | --- | --- |
| 冷启动 | < 1 s | 单次 `bootstrap`；首屏只查当天；CSS/JS 本地小文件 |
| 记录提交 | < 100 ms 感知 | 乐观更新 + 后端确认；失败回滚并保留输入 |
| 时间线 | 100 条/页 | 分页 + “加载更早”；避免一次渲染上千节点 |
| 搜索 | P95 < 100 ms（1 万条） | 索引、LIMIT、250 ms 防抖、取消过期请求（序号标记） |
| 统计 | < 200 ms | 单条 GROUP BY；热力图一次查询；结果缓存 30 s |
| 内存 | 常驻 < 250 MB | 不缓存全量记录；只保留当前视图数据 |

- 后端统计查询走覆盖索引；必要时加 `entry_date` 单列索引。
- 大批量导入用事务 + 预编译语句，每 500 条提交一次。
- 页面隐藏时暂停心跳事件（专注计时除外，由后端计时）。

## 8. 可靠性

| 场景 | 方案 |
| --- | --- |
| 写入失败 | 检查 `store.set` 返回值；SQLite 抛错捕获后转中文提示；输入不丢 |
| 数据库损坏 | 启动时 `PRAGMA integrity_check`；失败则提示从最近备份恢复，不自动覆盖 |
| 迁移失败 | 迁移前备份；事务回滚；版本号不变；应用以只读模式启动并提示 |
| 并发写 | SQLite 单连接 + `db.transaction()`；后端单线程，天然串行 |
| 崩溃恢复 | WAL 模式；启动时执行 `PRAGMA wal_checkpoint(TRUNCATE)`（备份前） |
| 误删 | 软删除 + 撤销；7 天后清理任务（可手动） |
| 备份占空间 | 保留 7 份；每份通常 < 5 MB；设置页显示总大小 |

## 11. 技术风险

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| `file://` 下多脚本加载顺序出错 | 中 | 白屏 | 严格顺序 + 启动自检 + `window.onerror` 提示 |
| SQLite `VACUUM INTO` 参数绑定不可用 | 低 | 备份失败 | 回退：`wal_checkpoint` 后 `tjs.copyFile` |
| 全局快捷键被占用 | 中 | 快速记录不可用 | 注册失败提示 + 设置内更换 + 应用内 `⌘N` 兜底 |
| 时间/时区处理错误 | 中 | 记录归错日期 | 统一 `entryDateFor()`；单元测试覆盖跨零点、月末、闰年 |
| 数据量增长导致统计变慢 | 低 | 卡顿 | 索引 + 缓存 + FTS 预案 |
| 迁移写坏数据 | 低 | 严重 | 迁移前备份 + 事务 + fixture 测试 |
| UI 状态与后端不一致 | 中 | 显示错误 | 写操作以返回值为准；事件驱动刷新；失败回滚 |

## 12. 后续演进

- **同步**：若未来要多设备，新增 `revision` / `updated_at` 冲突解决，导出格式升级到 v2；不建议直接接第三方后端。
- **FTS5**：`entries_fts` 虚拟表 + INSERT/UPDATE/DELETE 触发器；搜索接口不变。
- **附件**：文件放 `data/attachments/`，数据库只存相对路径与哈希；需处理清理与导出。
- **AI 摘要**：必须可选、默认关闭；优先本地模型或用户自带 Key；发送前明确提示将离开本机。
- **跨平台**：路径、快捷键修饰键、通知、托盘已通过 tinyjs 抽象；重点验证 Windows 的 `file://` 与字体。
