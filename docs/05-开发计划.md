# 05 · 开发计划

- 版本：v0.1
- 关联：[需求文档](01-需求文档.md) · [产品设计](02-产品设计.md) · [技术设计](03-技术设计.md)
- 节奏假设：单人开发，每天 2–4 小时；一个里程碑 = 一个可运行的版本，不追求一次性做完。

---

## 1. 交付策略

**先跑通一条完整链路，再扩功能。**

```text
M0 文档与骨架
 → M1 数据层 + 应用外壳（能存、能取、能切页）
 → M2 今日 + 记录 + 日报（核心闭环，自己先用起来）
 → M3 任务 + 项目（把“要做的事”接上）
 → M4 回顾 + 周报（产生交付价值）
 → M5 系统集成（快捷键、托盘、提醒、备份）
 → M6 P1 增强（模板、专注、片段、热力图）
 → M7 打磨与 v0.1 发布
```

每个里程碑结束时必须：

1. `tinyjs dev` 可启动，无控制台报错；
2. 当页功能可完整操作；
3. 数据在重启后仍在；
4. 更新本文档的“实际进度”与遗留问题。

## 3. 任务优先级排序（如果时间不够）

必须做（缺一不可）：

1. 记录 CRUD + 今日时间线 + 持久化
2. 日报 + 周报
3. 任务基础 CRUD + 完成
4. 项目 + 搜索
5. 备份 + 导出

可以砍（不影响核心闭环）：

- 拖拽排序（先用上下移动按钮）
- 热力图（先用数字统计）
- 项目详情页
- 托盘 / 全局快捷键（先用应用内 `⌘N`）
- 标签系统（先用项目 + 全文搜索）
- 专注 / 片段 / 深色模式
